# テスト駆動開発とテストリスト

このハンズオンでは，すべての機能をテスト駆動開発(TDD)で作る．
このガイドでは，テストリストの書き方，Rustでのテストの分け方と実行の仕方を説明する．

## Red → Green → Refactor

1つの振る舞いごとに，次の3つの段階を回す．

1. Red：まだない振る舞いを確かめるテストを1つ書き，実行して失敗することを確かめる．コンパイルエラーも失敗の1つである．
2. Green：テストが通る最小のコードを書く．定数を返すだけの仮実装でもよい．
3. Refactor：テストが通ったまま，重複をなくし，名前と構造を整える．

Redで失敗を確かめるのは，テストが正しい理由で失敗すること(テストが実行されていて，期待値を確かめていること)を知るためである．

## テストリスト

各Iterationの最初に，ロードマップの「要件」と「使用例」から，確かめるべき振る舞いを`TESTLIST.md`に書き出す．
テストリストは仕様書ではなく，これから書くテストの予定表である．

### 書き方

- 1項目に1つの振る舞いを書く．「〜のとき，〜になる」の形にすると，テストの名前にしやすい．
- 入力と期待する結果を具体的に書く．
- 正常な場合だけでなく，境界(空の入力，最大値)と異常な場合(エラー)も書く．
- 単体テストと結合テストを分けて書く．
- 実装を進めるうちに気づいた振る舞いは，その場で項目を足す．
- テストが通ったら，項目にチェックを付ける．

```markdown
## 単体テスト

### count

- [x] 空の文字列からは，空の一覧を返す
- [x] 「a b a」からは，aが2回，bが1回の一覧を返す
- [ ] 大文字と小文字は区別しない(「A a」はaが2回)

## 結合テスト

- [ ] 「b a b」の上位1件は「b 2」になる
```

### 並べ方

- 最も単純で，すぐに通せる項目から始める．
- 1つ前の項目を通したコードを少し広げれば通る順に並べる．
- エラーの項目は，正常な項目の実装が固まってから並べる．

### 既存のテストへの影響

新しい機能で既存のテストの期待値が変わるときは，「〜の期待値を〜に変える」という項目をテストリストに書く．
ロードマップの「既存テストへの影響」を手がかりに，変わるテストを探す．

## 単体テストと結合テスト

| | 単体テスト | 結合テスト |
| --- | --- | --- |
| 置き場所 | 各モジュールのファイルの末尾の`#[cfg(test)] mod tests` | パッケージの`tests/`の下のファイル |
| 呼べるもの | そのモジュールの関数(非公開のものも含む) | ライブラリの公開API(`pub`なもの)だけ |
| 確かめること | 1つのモジュールの関数の振る舞い | モジュールが組み合わさった，利用者から見た振る舞い |

単体テストは次のように書く．`use super::*;`で，親のモジュールの項目を使えるようにする．

```rust
pub fn count_words(text: &str) -> usize {
    text.split_whitespace().count()
}

#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn counts_words_separated_by_spaces() {
        assert_eq!(count_words("a b a"), 3);
    }
}
```

結合テストは`tests/`に機能ごとのファイルを作り，クレートを外から使うように書く．
ファイル名は機能の名前にする(`tests/count.rs`など)．

```rust
use wordfreq::run;

#[test]
fn shows_the_most_frequent_word_first() {
    assert_eq!(run("b a b", 1), "b 2\n");
}
```

## テストの実行

`cargo`のコマンドは，`Cargo.toml`のあるディレクトリ(演習では`exercise/`)で実行する．

| 目的 | コマンド |
| --- | --- |
| すべてのテスト | `cargo test` |
| 単体テストだけ | `cargo test --lib` |
| 1つの結合テストのファイルだけ | `cargo test --test count` |
| 名前に文字列を含むテストだけ | `cargo test empty` |
| テストの中の`println!`も表示する | `cargo test -- --nocapture` |

`assert_eq!`が失敗すると，1つ目の引数の値を`left`，2つ目の引数の値を`right`として表示する．
このハンズオンでは，1つ目に実際の値，2つ目に期待値を書く．
次は，上の単体テストの期待値を誤って`2`と書いたときの出力である．

```text
thread 'tests::counts_words_separated_by_spaces' (13495) panicked at src/lib.rs:11:9:
assertion `left == right` failed
  left: 3
 right: 2
```
