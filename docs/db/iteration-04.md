# Iteration 4：SQLSTATE

## SQLSTATE

SQLSTATEは，標準SQLが定めるエラーの種類のコードである．5文字の英数字で，前の2文字をクラス，後の3文字をサブクラスと呼ぶ．
利用者のプログラムは，メッセージの文面ではなくSQLSTATEでエラーの種類を判断する．

| クラス | 意味 | 例 |
| --- | --- | --- |
| `00` | 成功 | `00000` |
| `22` | データの例外 | `22003`(数値が範囲外)，`22012`(0での割り算) |
| `23` | 整合性制約の違反 | `23505`(一意性の違反，Iteration 8) |
| `25` | トランザクションの状態が不正 | `25P02`(失敗したトランザクションの中，Iteration 18) |
| `40` | トランザクションのロールバック | `40001`(直列化の失敗，Iteration 22) |
| `42` | 構文の誤りまたはアクセス規則の違反 | `42601`(構文の誤り)，`42804`(型の不一致) |

標準SQLはクラスと一部のサブクラスを定め，残りのサブクラスを実装に任せる．
`ferrodb`は，PostgreSQLと同じコードを使う．PostgreSQLのクライアントは，このコードでエラーを見分ける．

## エラーの位置

構文の誤りでは，PostgreSQLはSQLSTATE，メッセージに加えて，誤りのある位置を返す．
位置は，文の先頭の文字を1とした文字の番号である．`psql`は，この位置を使って誤りのある行を表示し，その下に`^`で誤りの箇所を示す．

文が途中で終わっているときは，`syntax error at end of input`になる．

実行中に起きるエラー(0での割り算など)は，文のどの部分が原因かをPostgreSQLは返さない．`ferrodb`でも，評価のエラーには位置を付けない．

## 構文解析の誤りの位置

構文解析器は，いくつかの読み方を順に試す．ある読み方が途中で失敗したとき，その読み方をやめて別の読み方を試すのがバックトラックである．
バックトラックすると，「最後に失敗した読み方」の位置ではなく，「どの読み方もできなかった位置」でエラーになり，誤りの位置が手前にずれることがある．

`(`や`,`のあとには式しか来ない，というように，文法上ほかの読み方がない位置では，それ以上バックトラックしないように構文解析器に伝える．
そうすると，誤りのあるトークンの位置でエラーを報告できる．
