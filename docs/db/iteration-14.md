# Iteration 14：ヒープファイルとデータディレクトリ

## データディレクトリ

データベースは，すべてのデータを1つのディレクトリの下に置く．このディレクトリをデータディレクトリと呼ぶ．
PostgreSQLでは，`initdb`で作り，サーバーの起動時に`-D`で指定する．`ferrodb`では`--data-dir`で指定する．

`ferrodb`のデータディレクトリには，次のファイルを置く．

```text
data/
  catalog       表の定義(カタログ)
  54.heap       表 T のヒープファイル
  5553455253.heap  表 USERS のヒープファイル
```

データディレクトリを指定しなければ，これまでどおりページをメモリーに置く．テストや試しに使うときは，ファイルを残さない方が扱いやすい．

## ヒープファイル

Iteration 13のヒープファイルは，ページの列をメモリーに置いた．Iteration 14では，ページを番号の順に並べてファイルに書く．
`n`番目のページはファイルの`n * 8192`バイト目から始まるので，ページ番号からファイルの中の位置がすぐに求まる．ファイルの大きさは，ページの数の8192倍である．

```text
0          8192       16384      24576
+----------+----------+----------+
| page 0   | page 1   | page 2   |
+----------+----------+----------+
```

- ページはいつも8192バイトをまとめて読み書きする．タプル1つを変えるときも，そのページ全体を読み，書き戻す．
- 新しいページは，ファイルの末尾に加える．
- 表ごとに別のファイルにすると，`DROP TABLE`はファイルを消すだけで済む．

PostgreSQLも，表ごとにファイルを作り，8192バイトのページを並べる．ファイルの名前は表の名前でなく，カタログが表に割り当てた番号(`relfilenode`)である．
`ferrodb`は，表の名前のUTF-8のバイトを16進数で書いた名前にする．表の名前には`/`や`.`など，ファイル名に使えない文字や特別な意味を持つ文字も入りうるが，16進数にすれば`0`〜`9`と`a`〜`f`だけになる．

## ページを読み書きする層

ヒープファイルは，ページを読み書きする層(`DiskManager`)を通してファイルを使う．ヒープファイルは「何番のページを読む」「何番のページを書く」とだけ頼み，ページがファイルにあるかメモリーにあるかを知らない．

```text
HeapFile            タプルを置くページを選び，ページの中を読み書きする
  ↓ ページ番号
DiskManager         ページ番号のページを読み書きする(ファイルかメモリー)
```

PostgreSQLでも，ページを読み書きする層(storage manager)が，ページ番号をファイルの中の位置に変換する．
今の`ferrodb`は，タプルを読み書きするたびにファイルのページを読む．Iteration 15では，読んだページをメモリーに残しておくバッファプールを，ヒープファイルと`DiskManager`の間に置く．

## カタログ

表の名前，列の名前と型，制約などの定義を，カタログ(システムカタログ)と呼ぶ．
ヒープファイルのタプルには列の型が書かれていないので，カタログがなければタプルを復号できない．起動するときは，まずカタログを読み，そこにある表のヒープファイルを開く．

- `ferrodb`は，カタログを1つのファイル`catalog`に書く．`CREATE TABLE`と`DROP TABLE`のたびに，すべての表の定義を書き直す．
- PostgreSQLのカタログは，それ自体が表(`pg_class`，`pg_attribute`など)である．表の定義を変えることは，カタログの表の行を変えることになる．

### 途中で止まっても壊れない書き方

カタログのファイルを直接書き直すと，書いている途中でプロセスが止まったとき，読めないファイルが残る．前の定義と新しい定義のどちらも失われる．
そこで，`catalog.tmp`に書いてから，名前を`catalog`に変える．名前の変更は1回の操作で置き換わるので，ファイルは前の中身か新しい中身のどちらかになる．

ただし，ファイルに書いた内容は，すぐにディスクに届くとは限らない．OSはしばらくメモリーに置いてから，まとめてディスクに書く．OSや電源が止まれば，書いたはずの内容を失うことがある．
ヒープファイルのページも同じである．また，`UPDATE`で行を別のページに移すときのように，1つの文が2つのページを書き換える途中で止まると，片方だけが書かれた状態が残る．
Iteration 19では，ページの変更を先にログ(WAL)へ書き，WALがディスクに届いてからコミットを完了とする．障害のあとは，WALから変更をやり直し，コミットしていない変更を取り消す．

## 起動の流れ

`ferrodb repl --data-dir DIR`は，次の順に進む．

1. データディレクトリがなければ作る．
2. `DIR/catalog`を読む．なければ，表のないカタログから始める．
3. カタログの表ごとに，ヒープファイルを開く．ページの数は，ファイルの大きさを8192で割って求める．
4. REPLを始める．

PostgreSQLのサーバーも，起動するとデータディレクトリの制御ファイルを読み，前回きちんと止まったかを調べる．止まっていなければ，WALから回復してから接続を受け付ける．
