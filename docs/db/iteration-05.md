# Iteration 5：カタログと表

## 表とスキーマ

リレーショナルデータベースは，データを表(テーブル)に入れる．表は行の集まりで，どの行も同じ列を持つ．
表の名前と，列の名前と型の並びを，表のスキーマ(定義)と呼ぶ．

```sql
CREATE TABLE users (id INTEGER, name VARCHAR(20))
```

## カタログ

データベースは，すべての表のスキーマをカタログ(システムカタログ)に記録する．
`INSERT`や`SELECT`を実行するときは，まずカタログで表と列を探し，型を調べる．
PostgreSQLのカタログ自体も表として実装されている(`pg_class`，`pg_attribute`など)．

`ferrodb`では，スキーマを持つ`Catalog`と，行を持つ部分を分ける．
行の置き場所は，Iteration 13でページ，Iteration 14でファイルに変わるが，カタログの役割は変わらない．

## 識別子

表や列の名前を識別子と呼ぶ．標準SQLには2種類の識別子がある．

- 通常の識別子：英字で始まり，英字，数字，`_`が続く．大文字と小文字を区別せず，大文字に正規化される．`users`，`Users`，`USERS`は同じ名前`USERS`である．
- 区切り識別子：二重引用符で囲む．大文字と小文字を区別し，キーワードや空白も名前に使える．`"users"`は`USERS`とは別の名前である．

PostgreSQLは，標準と違って小文字に正規化する．`ferrodb`は標準に従うので，結果の列名は大文字になる．

## データ型

| 型 | 値 |
| --- | --- |
| `INTEGER`(`INT`) | 32ビット符号付き整数 |
| `BIGINT` | 64ビット符号付き整数 |
| `BOOLEAN` | 真偽値 |
| `VARCHAR(n)` | 最大`n`文字の文字列 |

整数のリテラルは，`INTEGER`の範囲に収まれば`INTEGER`，収まらなければ`BIGINT`になる(PostgreSQLと同じ)．
`INTEGER`と`BIGINT`の演算の結果は，範囲の広い`BIGINT`になる．

## 代入の規則

`INSERT`で列に値を入れることを，標準SQLは「格納の代入」と呼び，型ごとに規則を定める．

- `NULL`はどの型の列にも入る．
- 数値は，列の型の範囲に収まれば入る．収まらなければ`22003`(数値が範囲外)である．
- 文字列は，列の長さ以下なら入る．長ければ`22001`(文字列の右側の切り捨て)である．標準SQLは，はみ出した部分が空白だけなら切り捨てて入れるが，`ferrodb`は常にエラーにする．
- 型が合わなければ`42804`(型の不一致)である．

## 文の原子性

1つの`INSERT`で複数の行を挿入するとき，途中の行でエラーが起きたら，その文で挿入したすべての行を取り消す．
文は全体として成功するか，何も変えないかのどちらかである．これを文の原子性と呼ぶ．
`ferrodb`は，すべての行を検査し終えてから表に加えることで，これを実現する．

## `VALUES`の行の数

`VALUES`の各行は，同じ数の値を持たなければならない．
`INSERT INTO t VALUES ...`の値の数は，列を指定しなければ表の列の数，指定すれば指定した列の数と等しくなければならない．
