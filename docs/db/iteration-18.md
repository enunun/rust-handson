# Iteration 18：トランザクションとMVCC

## トランザクション

トランザクションは，いくつかの文をまとめて，すべてを反映するか，何も反映しないかのどちらかにする単位である．

- `START TRANSACTION`で始め，`COMMIT`で変更を確定(コミット)し，`ROLLBACK`で変更を取り消す(中止)．
- トランザクションの外の文は，それだけを1つのトランザクションとして実行し，成功すれば自動でコミットする(自動コミット)．

トランザクションが守る性質を，頭文字をとってACIDと呼ぶ．

| 性質 | 意味 | `ferrodb`で実現するIteration |
| --- | --- | --- |
| Atomicity(原子性) | すべて反映するか，何も反映しない | Iteration 18 |
| Consistency(一貫性) | 制約を満たした状態から，制約を満たした状態へ移る | Iteration 8，17 |
| Isolation(隔離性) | 同時に動くトランザクションが互いに影響しない | Iteration 18，21，22 |
| Durability(永続性) | コミットした変更は失われない | Iteration 19 |

### 失敗したトランザクション

トランザクションの中で文がエラーになると，PostgreSQLはトランザクションを失敗した状態にする．
失敗したトランザクションでは，`ROLLBACK`(か`COMMIT`)までのすべての文を`25P02`で断る．`COMMIT`しても中止になる．
途中まで成功した変更だけを残す誤りを防ぐための規則である．

## MVCC

ある行を書き換えている間，ほかのトランザクションに，書き換える前の行を見せたい．
MVCC(Multi-Version Concurrency Control，多版の同時実行制御)は，1つの行の複数の版を表に残し，トランザクションごとに見える版を選ぶ方法である．

- `INSERT`は，新しい版を置く．版のヘッダーの`xmin`に，作ったトランザクションの番号を書く．
- `DELETE`は，版を消さずに，ヘッダーの`xmax`に，削除したトランザクションの番号を書く．
- `UPDATE`は，古い版の`xmax`を書き，新しい版を置く．`DELETE`と`INSERT`の組である．

```text
INSERT(xid 1)        UPDATE(xid 3)
+------------------+ +------------------+
| xmin=1 xmax=3    | | xmin=3 xmax=0    |
| (1, 'alice')     | | (1, 'alicia')    |
+------------------+ +------------------+
```

`ROLLBACK`は，トランザクションの状態を「中止」にするだけでよい．中止したトランザクションが作った版は見えず，削除した版は削除されていないものとして見える．書き戻す仕事はない．
PostgreSQLも同じ方法をとる．古い版は，`VACUUM`が片付けるまで表に残る．

## スナップショットと可視性

スナップショットは，「どのトランザクションの変更が見えるか」を決める情報である．

- 自分の番号(`xid`)
- スナップショットを作った時点で進行中のほかのトランザクションの番号(`active`)
- まだ始まっていない番号の始まり(`xmax`)．これ以上の番号のトランザクションは，スナップショットのあとに始まった

あるトランザクションの変更が見えるのは，自分自身の変更か，スナップショットを作る前にコミットしたトランザクションの変更である．
版が見えるのは，次の両方を満たすときである．

1. `xmin`のトランザクションの変更が見える．
2. `xmax`が0か，`xmax`のトランザクションの変更が見えない．

| `xmin` | `xmax` | 見えるか |
| --- | --- | --- |
| コミット済み | 0 | 見える |
| コミット済み | コミット済み | 見えない(削除済み) |
| コミット済み | 中止 | 見える(削除が取り消された) |
| コミット済み | 進行中の別のトランザクション | 見える(削除はまだ確定していない) |
| 中止 | 何でも | 見えない |
| 自分 | 0 | 見える |
| 自分 | 自分 | 見えない(自分が削除した) |

`ferrodb`は，文ごとにスナップショットを作る．PostgreSQLの既定の分離レベル`READ COMMITTED`と同じ時点である．Iteration 22では，トランザクションの最初の文でスナップショットを作る`REPEATABLE READ`も扱う．

## トランザクションの状態の記録

可視性の判定には，版の`xmin`と`xmax`のトランザクションが，コミットしたか中止したかを知る必要がある．
`ferrodb`は，トランザクションの状態をファイル`xact`に1バイトずつ記録する．PostgreSQLでは，同じ役割のファイルをCLOG(commit log)と呼び，トランザクションごとに2ビットを使う．

- データベースを開き直したとき，進行中のまま残ったトランザクションは中止したものとみなす．プロセスが止まって，コミットできなかったトランザクションだからである．
- トランザクションを始めるときにも状態を書く．書かなければ，開き直したあとに同じ番号を別のトランザクションに振り，止まる前のトランザクションの版を自分の版と取り違える．

## インデックスと版

版を置くたびに，インデックスにも項目を加える．古い版の項目は消さない．

- インデックスで引いた位置の版が見えるかを，表の版のヘッダーで確かめる．インデックスだけでは，見えるかどうかがわからない．
- 一意性の検査も，インデックスで見つかった版のうち，見える版だけを重なりとして数える．自分が削除した値は，同じトランザクションの中で入れ直せる．

PostgreSQLのインデックスも版の情報を持たず，表の版で可視性を確かめる．

## 表を作る文とトランザクション

PostgreSQLは，`CREATE TABLE`などもトランザクションの中で実行し，`ROLLBACK`で取り消せる．カタログも表として持ち，MVCCで版を管理するからである．
`ferrodb`のカタログはMVCCの外にあるので，表とインデックスを作る文と消す文は，トランザクションの外でだけ実行できる．PostgreSQLでも，`CREATE DATABASE`など一部の文は同じ理由でトランザクションの中で実行できず，`25001`を返す．
