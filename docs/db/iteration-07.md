# Iteration 7：名前解決と`WHERE`

## `SELECT`の処理の順序

`SELECT`の句は，書く順と処理する順が違う．

```sql
SELECT name, id * 10 AS score   -- 3. 選択項目を計算する
FROM users                      -- 1. 表の行を読む
WHERE id >= 2                   -- 2. 条件で行を絞り込む
```

選択項目の別名(`score`)は，`WHERE`より後で決まるので，`WHERE`の中では使えない．

## 名前解決(バインド)

構文解析の結果には，`id`や`name`といった名前が文字列のまま残っている．
名前解決(バインド)は，名前がどの表のどの列を指すかを決め，存在しない名前をエラーにする段階である．
名前解決のあとの式では，列を「行の何番目の値か」で指せるので，実行のたびに名前を探さなくてよい．

PostgreSQLでは，この段階を解析(analyze)と呼び，名前を解決して型を検査する．
`ferrodb`の名前解決は列の名前だけを扱い，型は行を評価するときに調べる．

## `WHERE`と3値論理

`WHERE`は，条件が`TRUE`になる行だけを残す．`FALSE`と`UNKNOWN`の行は残さない．

`users`の`age`が`30`，`NULL`，`25`の3行なら，次のようになる．

| 条件 | 残る行 |
| --- | --- |
| `age > 26` | `30`の行 |
| `NOT age > 26` | `25`の行 |

`NULL`の行では`age > 26`と`NOT age > 26`がどちらも`UNKNOWN`になるので，どちらの条件でも残らない．
「条件を満たす行」と「条件を満たさない行」を合わせても，すべての行にはならないことがある．

`WHERE`の条件は真偽値でなければならない．`WHERE id`のように整数を書くと型の誤りになる．

## 選択項目と列名

選択項目には，列，式，`*`を書ける．`*`は，表のすべての列を定義の順に並べたものである．

結果の列名は次のように決まる．

- `AS 別名`があれば，その別名になる．`AS`は省略できる(`SELECT id * 10 score`)．
- 列をそのまま書いた項目は，列名になる．
- それ以外の式の列名は，標準SQLでは実装が決める．`ferrodb`はPostgreSQLと同じ`?column?`にする．
