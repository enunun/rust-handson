# Iteration 12：集約とグループ化

## 集約関数

集約関数は，複数の行の値から1つの値を計算する．

| 関数 | 結果 | 値がないとき |
| --- | --- | --- |
| `COUNT(*)` | 行の数 | `0` |
| `COUNT(x)` | `x`が`NULL`でない行の数 | `0` |
| `SUM(x)` | 合計 | `NULL` |
| `AVG(x)` | 平均 | `NULL` |
| `MIN(x)`，`MAX(x)` | 最小，最大 | `NULL` |

- `COUNT(*)`以外の集約関数は，`NULL`を無視する．`NULL`しかなければ，値がないときと同じになる．
- `COUNT(DISTINCT x)`のように`DISTINCT`を付けると，同じ値を1度だけ使う．
- `ferrodb`の`AVG`は，整数の平均を0の方向に切り捨てた`BIGINT`を返す．PostgreSQLの`avg(integer)`は，小数を持つ`numeric`を返す．
- PostgreSQLの`sum(integer)`は`bigint`，`count`は`bigint`を返す．`ferrodb`も同じ型にする．

## `GROUP BY`

```sql
SELECT dept, COUNT(*) AS n, SUM(salary) AS total
FROM emp
GROUP BY dept
HAVING COUNT(*) > 1;
```

`GROUP BY`は，キーの値が等しい行を1つのグループにまとめる．集約関数は，グループごとに計算する．
キーの`NULL`どうしは，同じグループにまとまる．`DISTINCT`と同じく，`NULL`どうしを区別しない．

`GROUP BY`がなくても，選択項目に集約関数があれば，表全体を1つのグループにする．
このとき，行が1つもなくても，結果は1行になる(`SELECT COUNT(*) FROM 空の表`は`0`)．`GROUP BY`があれば，行がないとグループもないので，結果は0行になる．

## 集約する問い合わせで使える式

集約する問い合わせでは，結果の1行が1つのグループに対応する．
そのため，選択項目に書けるのは，グループの中で値が1つに決まる式だけである．

- `GROUP BY`のキーと同じ式
- 集約関数の呼び出し
- 定数と，上の式を組み合わせた式(`MAX(salary) - MIN(salary)`，`dept || '!'`)

`GROUP BY dept`で`name`をそのまま選ぶと，グループの中に名前が複数あるので，どれを返すか決まらない．これはエラー(`42803`)になる．

## 処理の順序と`HAVING`

```sql
SELECT dept, COUNT(*)      -- 5. 選択項目を計算する
FROM emp                   -- 1. 表の行を読む
WHERE salary >= 400        -- 2. 行を絞り込む
GROUP BY dept              -- 3. グループにまとめ，集約関数を計算する
HAVING COUNT(*) > 1        -- 4. グループを絞り込む
ORDER BY dept;             -- 6. 並べ替える
```

- `WHERE`はグループにまとめる前の行を，`HAVING`はまとめたあとのグループを絞り込む．
- `WHERE`の時点では集約関数の結果がまだないので，`WHERE`に集約関数は書けない．
- `HAVING`には，選択項目と同じく，キーと集約関数を使った条件を書く．

## ハッシュによる集約

`ferrodb`は，キーの値をハッシュ表で引いて，行を1つずつグループに振り分ける(ハッシュ集約)．
グループごとに，集約関数の途中の結果(件数，合計，最大値など)だけを持つので，グループの行そのものは覚えない．
表を1度読めば集約が終わるが，すべての行を読むまで最初のグループの結果を返せない．集約はブロッキング演算子である．

キーで並べ替えてから，隣り合う同じキーの行をまとめる方法(ソート集約)もある．PostgreSQLは，行の数の見積もりから2つの方法を選ぶ．

SQLは，`ORDER BY`がなければグループを返す順序を決めない．`ferrodb`は，グループが最初に現れた順で返す．
