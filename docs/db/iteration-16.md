# Iteration 16：B+木

## インデックス

ヒープファイルの行は，入れた順に並んでいるだけである．`WHERE id = 42`の行を探すには，すべてのページを読む(全件走査)．
インデックスは，列の値(キー)から行の位置(`RowId`)を引くための，別のファイルに置く構造である．
Iteration 16ではキーから`RowId`を引くB+木を作り，Iteration 17でそれを表のインデックスとして使う．

## B+木の形

B+木は，ページを1つのノードとする，高さのそろった木である．

```text
                [ 50 | 120 ]                      根(内部ノード)
               /     |      \
   [10 20 30 40] [50 70 90] [120 150 200]         葉
         ──────────→ ──────────→                  右隣の葉へのつながり
```

- 葉は，キーと`RowId`の組(項目)を，キーの順に並べる．葉は右隣の葉へのページ番号を持ち，すべての葉が1列につながる．
- 内部ノードは，区切りのキーと子のページ番号を並べる．区切りより小さいキーは左の子に，区切り以上のキーは右の子にある．
- 根から葉までの段数(高さ)は，どの葉でも同じである．

1つのノードに入る子の数(ファンアウト)は，ページの大きさとキーの大きさで決まる．`INTEGER`のキーなら，1つの内部ノードに500を超える子が入る．
高さ3の木で，およそ500 × 500 × 500 = 1億2500万の項目を引ける．1つのキーを探すのに読むページは，高さの数だけである．

### 検索

根から始めて，内部ノードでは区切りと比べて子を選び，葉まで下りる．葉の中は整列しているので，二分探索で項目を見つける．

### 範囲の走査

範囲の始まりのキーで葉まで下り，そこから葉のつながりを右へたどる．範囲の終わりを超えた項目で止まる．
`WHERE salary BETWEEN 400 AND 500`のような範囲の条件を，範囲の中の項目だけ読んで答えられる．

## 挿入と分割

項目は，キーの順を保つ位置に入れる．葉がページに入らなくなったら，葉を2つに分割する．

1. 項目を前半と後半に分け，後半を新しいページの葉に移す．
2. 右の葉の最初の項目を区切りとして，親の内部ノードに加える．
3. 親もページに入らなくなったら，親も分割し，真ん中の区切りをさらに上に送る．
4. 根を分割したら，新しい根を作る．木の高さはこのときだけ1段増える．

根から分割するので，葉はいつも同じ段にそろう．

根のページが変わるので，根のページ番号を決まった場所に書いておく．`ferrodb`はページ0(メタページ)に書く．PostgreSQLのB木のインデックスも，ページ0をメタページにしている．

## 削除

葉から項目を消す．`ferrodb`は，項目が少なくなったノードを隣と併合しない．
併合しなくても検索は正しく動くが，空に近いノードが残り，ページを無駄にする．
PostgreSQLも削除のたびには併合せず，`VACUUM`が空になったページを木から外す．

## 順序を保つキーの符号化

ノードの中のキーは，型を問わずバイト列として比べたい．そこで，バイト列を辞書式に比べた順序が，元の値の順序と同じになるように符号化する．

| 型 | 符号化 | 例 |
| --- | --- | --- |
| `INTEGER` | 符号ビットを反転して，4バイトのビッグエンディアン | `-1`は`7f ff ff ff`，`0`は`80 00 00 00`，`1`は`80 00 00 01` |
| `BIGINT` | 同じく8バイト | |
| `BOOLEAN` | 偽は`00`，真は`01` | |
| `VARCHAR` | UTF-8のバイト列 | `a` < `ab` < `b` |

- リトルエンディアンでは下位のバイトが先に来るので，バイト列の比較が数の順にならない．上位のバイトが先に来るビッグエンディアンで書く．
- 2の補数では，負の数の最上位ビットが1なので，そのままでは負の数が正の数より大きく見える．符号ビットを反転すると，負の数が`00`から，正の数が`80`から始まる．
- UTF-8のバイト列の順序は，文字の番号(Unicodeのコードポイント)の順序と同じである．`ferrodb`の`VARCHAR`の順序も文字の番号の順序なので，そのまま使える．

PostgreSQLは，キーを型ごとの比較関数で比べる．`VARCHAR`は照合順序(collation)に従い，言語によってはバイト列の順序と違う．

## 同じキーの項目

一意でない列のインデックスには，同じキーの項目がいくつも入る．
`ferrodb`は，項目をキーと`RowId`の組で並べ，同じキーの項目を`RowId`で区別する．

- 区切りもキーと`RowId`の組なので，同じキーの項目が多くの葉にまたがっても，分割と検索が正しく動く．
- 削除では，キーと`RowId`の両方で項目を特定する．表の1行を消したとき，その行の項目だけを消せる．

PostgreSQL 12以降のB木のインデックスも，同じキーの項目を行の位置(TID)で並べる．
