# Iteration 3：文字列型

## 文字列リテラル

標準SQLの文字列リテラルは，単一引用符`'`で囲む．
文字列の中に`'`を書くときは，`''`のように2つ重ねる．

```sql
VALUES ('it''s')   -- it's
```

二重引用符`"`は文字列ではなく，Iteration 5で扱う識別子(表や列の名前)を囲む．

## 文字列型

標準SQLの文字列型には，固定長の`CHARACTER(n)`と可変長の`CHARACTER VARYING(n)`(`VARCHAR(n)`)がある．
`ferrodb`は可変長の`VARCHAR`だけを扱う．文字列リテラルの値は`VARCHAR`になる．
長さ`n`の上限は，Iteration 5で表の列に型を付けるときに扱う．

## 連結

`||`は2つの文字列をつなぐ．片方が`NULL`なら，結果は`NULL`になる．

```sql
VALUES ('abc' || 'def', 'abc' || NULL)   -- abcdef と NULL
```

`ferrodb`では，`||`は加減算より弱く，比較より強い(PostgreSQLと同じ)．
`1 + 2 || 'x'`は`(1 + 2) || 'x'`と読まれ，整数と文字列の連結なので型の不一致になる．

## 照合順序

文字列の大小は，照合順序(collation)で決まる．照合順序は，言語ごとの辞書順や，大文字と小文字を区別するかなどを定める．
標準SQLは照合順序を指定する構文を持ち，既定の照合順序は実装が決める．

`ferrodb`は，Unicodeのコードポイントの順に比べる．PostgreSQLの照合順序`C`と同じ結果になる．

- 大文字は小文字より小さい(`'B' < 'a'`)．
- 短い文字列は，それで始まる長い文字列より小さい(`'ab' < 'abc'`)．
- 先頭から比べ，最初に違う文字で決まる(`'ab' < 'b'`)．

## エラーの位置

PostgreSQLは，エラーの位置を「文の先頭から何文字目か」で返す．バイトの数ではない．
文字列に日本語などを含む文でも，エラーの位置が画面上の文字の位置と一致する．
