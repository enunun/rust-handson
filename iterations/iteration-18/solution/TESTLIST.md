# テストリスト

## 単体テスト

### txn

- [x] トランザクションの番号は1から振り，コミットと中止で状態が変わる
- [x] スナップショットは，自分のほかに進行中のトランザクションと，次に振る番号を持つ
- [x] 自分が作った版は見え，自分が削除した版は見えない
- [x] コミット済みのトランザクションが作った版は見え，中止したトランザクションが作った版は見えない．削除が中止された版は見える
- [x] スナップショットを作ったときに進行中だったトランザクションの変更は，あとでコミットしても見えない．新しいスナップショットでは見える
- [x] 状態をファイルに保存して読み込むと，進行中のまま残ったトランザクションは中止になる
- [x] 状態のファイルがなければ，番号を1から振る

### storage::tuple

- [x] タプルは，`xmin`と`xmax`の8バイトのヘッダーのあとに行の値を並べる．ヘッダーと値を分けられ，途中で終わるタプルはエラーになる

### storage::heap

- [x] `rows`は，渡した関数が真を返すヘッダーの版だけを返す
- [x] `set_xmax`は版の`xmax`だけを書き換える．ない版なら`false`を返す

### sql::parser

- [x] `START TRANSACTION`，`COMMIT`，`ROLLBACK`．`START`だけではエラーになる

### exec::dml

- [x] (変更)テストの表を，トランザクションで行を加えてコミットした表にし，操作をそれぞれのトランザクションで行う
- [x] 加えた版の`xmin`は，加えたトランザクションの番号である
- [x] `UPDATE`は古い版の`xmax`を書き，新しい版を加える．古い版は表に残る
- [x] (変更)`UPDATE`のあと，インデックスで引けるのは新しい版だけである
- [x] (変更)`UPDATE`した行は，新しい版として表の最後に並ぶ
- [x] (変更)`DELETE`した行は見えなくなるが，版は表に残る
- [x] 削除した値は，もう一度加えられる
- [x] 中止したトランザクションが加えた行は見えず，同じ値をもう一度加えられる

### error

- [x] 失敗したトランザクションは`25P02`，トランザクションの中の`START TRANSACTION`と表を作る文は`25001`になる

### format

- [x] `START TRANSACTION`，`COMMIT`，`ROLLBACK`のコマンドタグ

## 結合テスト

### transaction

- [x] `ROLLBACK`すると，トランザクションの中の変更が消える
- [x] `COMMIT`すると，変更が残る
- [x] 同じ行を2回書き換えても，`ROLLBACK`で最初の版に戻る
- [x] エラーのあとは`ROLLBACK`まで`25P02`になり，`COMMIT`は`ROLLBACK`になる
- [x] 構文のエラーもトランザクションを失敗させる
- [x] トランザクションの中の`START TRANSACTION`は`25001`で，トランザクションは続く
- [x] トランザクションの中の`CREATE TABLE`は`25001`で，トランザクションは失敗する
- [x] トランザクションの外の`COMMIT`と`ROLLBACK`は何もしない
- [x] トランザクションの外で失敗した文は，何も変えない
- [x] 開き直すと，コミットしたトランザクションの変更だけが残り，進行中だった行の値は再び使える
- [x] インデックスで読んでも，全件走査と同じ版が見える

### repl

- [x] プロンプトは，トランザクションの中で`ferrodb*>`，失敗したトランザクションの中で`ferrodb!>`になる

### そのほか(既存)

- [x] (変更)`row is too big`の大きさはヘッダーの8バイトを含み，ページに入る最大の文字列は8173文字になる
- [x] (変更)データディレクトリに`xact`がある
- [x] (変更)`UPDATE`したあとの行の順序によらないように，`ORDER BY`で並べて比べる
- [x] 引き継いだそのほかの結合テストがすべて通る
