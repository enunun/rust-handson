# テストリスト

## 単体テスト

### sql::parser

- [x] `CREATE INDEX 名前 ON 表 (列)`は，名前，表，列を持つ．列を2つ書くとエラーになる
- [x] `DROP INDEX 名前`

### catalog

- [x] 一意性制約ごとに，制約と同じ名前のインデックスの定義ができる
- [x] 作ったインデックスの定義を名前と表で引け，消せる
- [x] インデックスの名前は，ほかのインデックスや表の名前と重ならない．表の名前もインデックスの名前と重ならない
- [x] ない表のインデックスは作れない
- [x] ないインデックスと，一意性制約のインデックスは消せない
- [x] 表を消すと，表のインデックスの定義も消える
- [x] 保存したカタログを読み込むと，インデックスの定義も戻る

### index

- [x] 列の型のインデックスに`Value`で項目を加え，値と範囲で行の位置を引ける．同じ値は行の位置の順に並ぶ
- [x] `NULL`は加えない
- [x] 消した項目は引けない
- [x] 開き直したインデックスで，同じ項目を引ける
- [x] 2000バイトを超える文字列はキーにできない

### plan::planner

- [x] インデックスのある列の`=`の条件は，`IndexScan`になり，`Filter`は残らない
- [x] 同じ列の範囲の条件は，狭い方にまとめる
- [x] `定数 比較 列`の条件は，向きを変えて使う
- [x] インデックスで決められない条件は，`IndexScan`の上の`Filter`に残る
- [x] `=`の条件のあるインデックスを優先する
- [x] `OR`，`<>`，列の型にできない定数，`NULL`，結合の`WHERE`には，インデックスを使わない
- [x] (変更)インデックスのある列の`WHERE`は，`Filter`でなく`IndexScan`の上に演算子が重なる

### exec::index_scan

- [x] 渡した行を順に返す

### exec::dml

- [x] (変更)テストの表を，`ID`と`EMAIL`のインデックスと一緒に作って渡す
- [x] (変更)`NOT NULL`の列の`NULL`は違反である
- [x] インデックスにある値を加えると一意性制約の違反になる
- [x] 加える行どうしで値が重なっても違反になる
- [x] 一意性制約の列には，`NULL`をいくつも加えられる
- [x] 加えた行は，表とインデックスの両方にある
- [x] 書き換えると，インデックスの項目も新しい値と位置に変わる
- [x] 一意性は，すべての行を書き換えたあとの値で調べる(`ID = ID + 1`)
- [x] 消した行は，インデックスからも消える

### error

- [x] ないインデックスは`42704`，一意性制約のインデックスを消すのは`2BP01`，大きすぎるキーは`54000`になる

### format

- [x] `CREATE INDEX`と`DROP INDEX`のコマンドタグ

## 結合テスト

### index

- [x] `CREATE INDEX`のあと，範囲の条件の`EXPLAIN`は`IndexScan`になり，キーの順に行を返す
- [x] `PRIMARY KEY`の列の条件には，自動で作ったインデックスを使い，残りの条件は`Filter`になる
- [x] インデックスを使っても，全件走査と同じ行を返す
- [x] 行を加え，書き換え，消したあとも，インデックスで正しい行を引ける
- [x] `DROP INDEX`のあとは，`SeqScan`に戻る
- [x] 名前の重なり，ない表，ない列，ないインデックス，制約のインデックスを消すことはエラーになる
- [x] 一意性制約の違反はインデックスで見つかり，`ID = ID + 1`は成功する
- [x] キーにできない値の行があれば，`CREATE INDEX`はエラーになり，インデックスを作らない
- [x] インデックスは開き直しても残り，表を消すとインデックスのファイルも消える

### そのほか(既存)

- [x] 引き継いだ結合テストがすべて通る
